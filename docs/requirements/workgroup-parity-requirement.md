# 背景

## 产品定位

**【已确认】** 实施书与 `TECHNICAL_BLUEPRINT.md` 要求：

- 工作群以原版 DS Bot 群聊 UI、组件、样式和交互为基准制作；
- 原版普通群聊完整保留，与工作群互不干扰；
- 工作群在复刻原群聊的基础上增加跨用户协作能力；
- 不允许另起一套群聊 UI；
- 工作群为真实用户跨机器协作：Hub 建群、真人按邀请加入、Bot 以「所有者 + Bot」参与、消息由 Hub 排序、任务须 Bot 所有者本人审批。

# 目标

**【已确认】** 本需求完成后应达到：

1. **同一个产品**：工作群呈现原群聊的页面结构、消息样式、输入方式、成员区、设置与详情、侧栏菜单；工作群专属元素（Hub 状态、审批、任务进度、群记忆、Bot 所有者）以增量方式长在同一套视觉里。
2. **原群聊能力无静默缺失**：以当前仓库原群聊行为为基线逐项核对，每项必须有归宿——直接复刻、按工作群模型适配、或已裁决替换并登记差异。
3. **新建工作群即完成初始化**：进入即有主持管理员 Bot 发出的开场与完整群信息，可立即发言。
4. **管家 Bot 体系落地**：创建者至多带 1 个自己的管家 Bot 入群并主持；其他成员的管家 Bot 入群后同为管理员但不主持。
5. **原群聊完全不受影响**：原群聊的创建、聊天、成员、设置、历史、侧栏、删除/归档及数据保持原样。

# 核心功能

## 功能 1：新建工作群与初始化

- **触发**：点击「创建工作群聊」。
- **用户操作**：填群名称（可留空，按成员自动生成）、至多选择 1 个自己的管家 Bot、选择其他 Bot（不限，受每人 12 上限）、可选邀请同事、提交。
- **系统行为**：
  - 创建者成为群主；
  - **创建者选定的管家 Bot 成为主持管理员**；未显式选择时按原群聊缺省规则取其首个已发布管家 Bot；首个未发布时可用下一个已发布的；完全没有已发布的管家 Bot 时**阻止建群并明确提示**；
  - **成员下限 2 个 Bot**（与原群聊一致）：创建者必须再选至少 1 个自己的其他 Bot，或先邀请并等同事带上 Bot；
  - **邀请同事是可选的，允许先建群、后邀请**；
  - 界面结构与视觉复刻原群聊创建表面；
  - 创建成功直接进入群会话；
  - **由主持管理员 Bot 发出开场**（问候并询问群目标），不是空白会话。
- **最终结果**：建完群就能看到「谁在管、要做什么」，可立即发言。

## 功能 2：群会话主体与消息展示

- 以原群聊方式呈现：发送者标识、按发送者归组的消息块、气泡排版、时间与日期分隔、消息动作（复制 / 下载 / 表情反应 / 回复）、管理员 Bot 的 `Admin` 标记；
- Bot 以 Bot 身份、真人以真人身份呈现，自己的消息在自己一侧；
- 顺序以 Hub 群内顺序为准，不重排不重复；
- **支持向上加载更早消息**（原群聊能力，工作群当前缺失）。

## 功能 3：输入区与发送

- 输入区占满可用宽度、可输入、可多行、自动增高、内容不被截断；
- 发送成功即入时间线；失败保留草稿并显示「未送达」；
- `+` 菜单三项同位置同交互（添加文件 / 引用会话 / 定时任务）；引用仅限有权读取的数据；定时任务不得绕过审批；
- **听写麦克风**可用；
- **语音聊天不出现**（原群聊群内本身不提供）。

## 功能 4：成员、Bot 与管理员管理

- 成员列表同时展示真人与 Bot；真人显示在线状态，Bot 显示所有者与 `Admin` 标识；
- **归属原则**：任何成员只能管理、增添、移除**归属于自己**的 Bot；
- **每位成员至多 1 个自己的管家 Bot 在群内**，按最终在群数量判定；
- **每位成员在本群内名下的 Bot 总数 ≤ 12（含其管家 Bot）**；不同成员各自独立计数，全群总量无上限；
- 同事先作为真人被邀请、接受后进群，进群后自带 Bot；
- 任何成员可直接加入自己的 Bot；邀请他人 Bot 需 owner/admin 身份且需对方同意；
- owner/admin 可移除任何人的 Bot；普通成员只能移除自己的；移除成员时其名下所有 Bot 一并移除；
- **主持管理员移交与离群按原群聊规则**：离群前必须先移交；无法移交时进入「无主持管理员」状态，普通消息按「每人轮流」应答。

## 功能 5：群设置

- 结构与视觉复刻原群聊：群名、公告、成员与管理员、应答模式、工作目录、群级权限、侧栏置顶/隐藏、群管理；
- **从侧栏右键菜单进入时打开与原群聊一致的入口（全局设置页群聊页并定位到该群）**；
- **工作目录按原群聊口径**：群目录**覆盖每个成员 Bot 自己的目录**，所有成员在该群的 Session 都建在群目录下；可由群主或管家 Bot 设置；
- **群级权限按原群聊口径**：对全群成员生效；仅**群主**可设置。

## 功能 6：群详情与成员状态

- 公告、成员、成员状态、任务进展、群记忆；
- 「停止成员工作」映射为取消该 Bot 的进行中任务或停止其授权，不跨设备结束他人本地进程。

## 功能 7：@、回复与引用

- 提及绑定稳定身份；普通成员点名只召集被点名者，**`@all` 只有管理员可召集全体**；
- @ 他人 Bot 只产生待审批任务；
- 回复目标必须属于同一工作群；引用他人私人会话默认拒绝。

## 功能 8：Bot 参与任务并在群内发言

- 群内先出现脱敏进度；成果被所有者分享后，**以该 Bot 身份在群会话中出现一条发言，正文对全群广播**；
- **分享同时把成果附件对全群开放下载**；
- 未分享前正文与附件都不可见；拒绝/取消/撤销后不产生新发言。

## 功能 9：侧栏会话行与右键菜单

- 工作群以原群聊会话行形态出现（头像、名称、成员摘要、预览、时间、未读与提示），带工作群标识与 Hub 状态；新建成功的群立即出现；
- **右键菜单与原群聊房间菜单对齐（7 项）**：置顶/取消置顶、标为未读、群设置、重命名群聊、复制对话 ID、从侧栏隐藏、**解散**（占据原群聊「删除群聊」的位置、图标与危险样式）。

## 功能 10：未读与提示

- **两套机制并存、职责分开**：Hub 计数表示「有新消息」，本地「标为未读」标记表示「我要稍后看」；
- 打开会话时清理本地标记，Hub 计数按既有规则消减；
- 徽标同时体现待审批提示。

## 功能 11：表情反应

- 与原群聊一致的操作与呈现：消息动作里添加、气泡下方展示、点击撤销；
- **反应对全群成员可见**；
- **撤销语义沿用原群聊：点自己加的那个反应即可取消**，不提供撤销他人反应。

## 功能 12：Hub 状态、离线与恢复

- 显示在线/重连中/离线；离线不影响私聊、普通群聊、本地 Bot；未确认送达不显示成功；重连按序补拉不重复不乱序。

## 功能 13：解散工作群

- **按原群聊口径：群主、群主的主持管理员 Bot、Hub 管理端可解散**；其他成员的管家 Bot、真人管理员、普通成员**不可**；
- 从侧栏菜单、群设置页两处均可发起，均需确认；
- 撤销待处理邀请；取消未完成任务；历史只读保留；群内解散与 Hub 管理端解散结果完全一致。

# 已登记的模型差异

## D1：群级工作目录与群级权限按原群聊放开，取代实施书原有的禁止条款

- **原群聊事实（F29–F31）**：`workDirOf` 先取 `room.workDir`，取不到才回退到 `bot.workDir`——群目录**覆盖**每个成员 Bot 自己的目录；设置目录时会在本机弹出审批（目录在团队目录之外且沙箱为 `workspace-write` 时）；群级权限由 `setRoomPermission` 下发给所有成员，措辞为「every member now works with the X permissions here」。
- **本需求裁决**：工作目录与群级权限**按原群聊**实现，即群目录与群权限对**全群成员（含其他用户的 Bot）**生效；群权限仅群主可设。
- **与旧文档的冲突**：`TECHNICAL_BLUEPRINT.md` 与实施书原文写「不设跨用户共享的群级目录」「不设跨用户共享的群级执行权限」「由任务审批范围决定」。本裁决**取代**这些条款，需在实现计划阶段同步更新该文档。
- **必须保留的底线**：**跨用户任务**（他人委托给某个 Bot 的工作）仍须 **Bot 所有者本人审批**；群目录与群权限是执行环境的默认值，不构成对他人 Bot 的执行授权。**群主的主持管理员应答群内普通消息不属此类**，见 D2。
- **残留风险（实现阶段必须处理，不阻塞需求）**：目录审批在原群聊是本机用户弹窗。工作群中群主设置目录时只有群主本机弹窗；其他成员的 Host 如何接受该目录需在实现阶段确定落地方式（建议：其他成员 Host 在本机首次以该目录执行前仍需本机确认）。

## D2：主持管理员应答普通消息不走逐条任务审批，改由 Bot 自身权限预设与提示词决定

- **原群聊事实**：群里普通消息直接投递给管理员 Bot 的群 Session，它像任何一次正常对话一样作答；是否读文件、改文件、执行命令，由该 Bot 的**权限预设**（sandbox + approval policy）决定；预设为 `ask` 时，弹窗由本机用户在 Bot 自己的审批卡上应答。
- **本需求裁决**：工作群的主持管理员应答**沿用同一模型**——普通消息不是「待审批任务」，而是**直接进入该 Bot 的会话**。是否询问用户、是否自主决策，由该 Bot 的**记忆与提示词**决定（例如用户对它说过「你自己决定，不用问我」）。
- **与 R17/R22 的边界**：R17/R22 收窄为「**他人委托的跨用户任务**必须所有者本人批准」。主持管理员处理**群主自己的群**里的普通消息，属于所有者授权其管家在本群工作的常规行为，不构成代替他人审批。
- **仍然存在的硬约束（不可绕过）**：
  1. Bot 的工具调用受其**权限预设**约束；预设为 `ask` 时仍需本机用户应答（`approval/request` 由 DS Bot 在群内卡片上应答）。
  2. 群级权限（R34）会覆盖成员 Bot 在本群的预设——这决定「主持管理员在群里到底能自主到什么程度」。
  3. 撤销、取消、审计照常记录。
- **实现含义（供技术设计）**：主持应答**不是** `createTask` 路径；它必须走「把消息投递进该 Bot 在此群中的会话」这条原群聊已有的路径。因此工作群需要一类**长期的、属于该群的主持 Bot 会话**，而不是一次性任务 Session。

# 状态与生命周期

## 工作群

```text
创建成功 → 初始化中（主持管理员生成开场）
        ├─ 开场成功 → 存续（已初始化，可聊天）
        └─ 开场失败 → 存续（降级呈现，可聊天）
存续 ├─ 群主解散 ─────────┐
     ├─ 主持管理员 Bot 解散 ├→ 已解散（历史保留、只读）
     └─ Hub 管理端解散 ────┘
```

- 初始状态：创建成功即进入初始化，初始化完成前不呈现为空白群。
- 允许解散：群主、群主的主持管理员 Bot、Hub 管理端。
- 禁止解散：其他成员的管家 Bot、真人管理员、普通成员。
- 终态：已解散，不可恢复发送、邀请、改设置、发起任务。
- 是否允许恢复：当前按不可恢复处理。

## 邀请（真人，可选）

```text
待处理 → 接受 → 成为成员（可带入自己的 Bot）
       → 拒绝 → 已拒绝
       → 过期 → 已过期
       → 群解散 → 已撤销
```

## Bot 成员关系与管理员身份

```text
Bot 未加入 → 本人加入（直接）/ 他人邀请（需同意）/ 建群时自动 → 已加入
已加入 ┬─ 群主的管家 Bot → 主持管理员（Admin + 默认应答 + 可解散 + 可设目录）
       ├─ 其他成员的管家 Bot → 管理员（Admin，不主持，不可解散）
       └─ 其他 Bot → 普通 Bot 成员
约束：每位成员「管家 Bot ≤ 1」；「本人的 Bot 合计 ≤ 12」
已加入 → 移除 / 所有者退群 → 已移除（不再被 @、不再承接新任务、失去管理员身份）
```

## 主持管理员

```text
有主持管理员 ── 移交主持权 → 新的主持管理员
             ── 离群（未移交）→ 无主持管理员（不自动补位）
无主持管理员 → 普通消息按「每人轮流」应答；无 Bot 可解散群（群主与 Hub 仍可）
```

## 任务（工作群专属）

```text
待审批 → 拒绝/过期（终态）
       → 已批准 → 排队 → 执行中 → 待复核 → 已完成 → 已分享（正文与附件对全群可见）
                        → 取消中 → 已取消
                        → 失败 → 已失败
```

群解散时未完成任务必须取消。

## Hub 连接

```text
在线 ↔ 重连中 ↔ 离线
```

离线只影响工作群。

# 边界情况

- 建群时群名留空（按成员自动生成）。
- 创建者全部管家 Bot 均未发布（阻止创建）。
- 创建者首个管家未发布、第二个已发布（用第二个）。
- 建群时只选自己的管家 Bot、未选其他 Bot（低于 2 个下限，不允许）。
- 建群时未邀请任何同事（群内仅创建者与其 2 个 Bot）。
- 创建者带入 12 个自己的 Bot（达到每人上限）。
- 同事接受邀请后带入 1 个管家 Bot + 11 个其他 Bot（达到自己的上限）。
- 同事尝试带入第二个自己的管家 Bot。
- 同事尝试移除他人名下的 Bot。
- 开场生成失败或超时。
- 群内只有开场一条内容，没有真人发言。
- 主持管理员未移交即离群；主持管理员所有者被移出群。
- 无主持管理员时尝试由 Bot 解散（应无 Bot 可执行）。
- 成员被移除，其名下多个 Bot 一并移除。
- 群主或管家 Bot 设置群工作目录后，其他成员 Bot 在该目录执行。
- 群主设置群级权限后，其他成员 Bot 按该权限执行。
- 消息超过一页（200 条）后向上翻页。
- 表情反应：多人对同一消息加同一表情、他人尝试撤销、跨设备打开。
- 侧栏：群已解散后右键菜单；标为未读后收到新消息；隐藏后能否搜索到。
- 同一消息重复发送、重连后重复补拉、发送中 Hub 断线。
- 被 @ 的 Bot 已被移除或已离群。
- 任务已批准但执行中 Bot 被移除、所有者退群或群被解散。
- 成果被分享两次；分享后附件权限被收回。
- 群已解散，用户仍在旧会话中操作。

# 异常行为

| 情况 | 用户应看到 | 系统应保持 |
|---|---|---|
| 创建失败（Hub 不可用 / 无已发布管家 Bot / 不足 2 个 Bot） | 明确失败原因，停留在创建界面 | 不产生半成品群，不重复建群 |
| 群已创建但邀请失败 | 群照常打开，一次性提示失败对象 | 不重复建群，失败邀请不改为已加入 |
| 尝试带入第二个管家 Bot | 明确提示每位成员只能带一个管家 Bot | 请求被拒绝，成员构成不变 |
| 尝试带入第 13 个自己的 Bot | 明确提示已达每人上限 | 请求被拒绝 |
| 尝试操作他人名下的 Bot | 明确提示无权限 | 状态不变 |
| 开场生成失败 | 可解释的降级提示，群仍可用 | 不显示空白；不伪造 Bot 发言；可重试 |
| 主持管理员未移交即离群 | 明确提示需先移交主持权 | 拒绝该操作，成员与主持不变 |
| 因所有者退群导致主持位为空 | 提示当前无主持管理员 | 群仍可用，普通消息按轮流应答；无 Bot 可解散 |
| 无权限者尝试解散 | 与原群聊一致的提示 | 群状态不变 |
| 设置群工作目录时本机无法征求同意 | 明确提示无法完成，什么都没改 | 目录不变 |
| 发送失败 | 「未送达」+ 草稿保留 | 不写入被视为成功的消息；不产生重复 |
| 更早消息加载失败 | 可重试提示 | 已加载内容不丢失、不重复 |
| 目标 Bot 不可用/已离群 | 明确提示不可用 | 不生成指向该 Bot 的新任务 |
| 表情反应写入失败 | 反应不显示或回退，并有轻提示 | 不出现他人看不到的「已加」假象 |
| 撤销他人反应 | 不提供该操作 | 该反应保持不变 |
| 附件下载无权限 | 明确提示无权访问 | 不泄露附件内容 |
| 群已解散 | 明确提示已解散 | 拒绝发言、邀请、改设置、发起任务 |
| Hub 重连 | 从离线/重连中恢复在线 | 消息不重复、不乱序 |

# 保持不变

- 原群聊的创建、聊天、成员、设置、详情、记忆、历史、删除/归档行为与数据。
- 原群聊侧栏房间行的 7 项右键菜单行为与删除语义。
- 私聊与本地 Bot 的原有行为，Hub 离线时照常可用。
- 工作群执行授权模型：Bot 所有者本人审批；分享前成果正文与附件都不可见。
- 邀请机制（按用户 ID、需明确接受、有效期）。
- 消息幂等、群内顺序、断线补拉语义。
- 群记忆的服务端访问控制。
- 现有 Bot 加入/移除的权限模型（本人直接加入、owner/admin 邀请他人、成员移除连带其 Bot）。
- 不新增工作群一级导航入口。
- 不把历史私人 Bot 记忆或原群聊历史自动并入工作群。
- 既有工作群数据不丢失；历史工作群不做任何回填或改造。

# 需求冲突

**无未决冲突。** 以下为已裁决并登记的事项：

1. **D1（已裁决）**：工作目录与群级权限按原群聊放开，取代实施书的禁止条款；执行仍需所有者审批；残留的本机审批落地方式留待实现阶段。
2. **旧文档规则作废**：上一版本文档中「Bot 不是群管理员，不能代替所有者审批」已拆分处理——**Bot 可为群管理员（管家 Bot）**，但**仍不能代替所有者审批**。本版 R15/R16/R17 为准。
3. **「删除群聊」→「解散」**：保留原菜单的位置、图标、危险样式与二次确认；文案改为「解散工作群聊」，确认提示说明历史保留；仅对有权限者可用。
4. **表情「只能撤销自己的」为新增能力**：原群聊反应是本机存储、不记录谁加的（F16）；「对全群可见 + 与原群聊一致的撤销」叠加后必须按人记录反应并校验撤销者身份。

# 验收标准

## 主流程

1. Given 用户点击「创建工作群聊」，When 确认名称、选择自己的管家 Bot 与至少 1 个自己的其他 Bot 后创建，Then 创建成功、用户成为群主、直接进入群会话，群内已有主持管理员 Bot 发出的开场内容（问候并询问群目标）。
2. Given 建群时群名留空，When 创建成功，Then 群名按成员自动生成（与原群聊一致）。
3. Given 建群成功，When 查看成员列表，Then 创建者的管家 Bot 已在群内并显示为**主持管理员**。
4. Given 创建者已发布两个管家 Bot 而首个未发布，When 建群，Then 使用**已发布的那个**作为主持管理员。
5. Given 创建者没有任何已发布的管家 Bot，When 尝试建群，Then **阻止创建**并明确提示。
6. Given 创建者只选了自己的管家 Bot、没有其他 Bot 且未邀请同事，When 提交创建，Then **不允许创建**并说明至少需要 2 个 Bot。
7. Given 建群时未邀请任何同事，When 创建成功，Then 群正常可用，可后续再邀请同事。
8. Given 被邀请的同事，When 接受邀请，Then 成为群成员；未接受前不可访问群内容。
9. Given 已进群的同事，When 带入自己的 1 个管家 Bot 与若干其他 Bot，Then 全部成功加入，管家 Bot 显示 `Admin` 但**不主持**默认应答。
10. Given 已进群的同事，When 尝试带入**第二个**自己的管家 Bot，Then 请求被拒绝并说明每位成员只能带一个。
11. Given 某成员名下已有 12 个 Bot，When 再带入第 13 个，Then 请求被拒绝并说明已达上限；其他成员不受影响。
12. Given 成员 A，When 尝试移除成员 B 名下的 Bot（A 非 owner/admin），Then 请求被拒绝并提示无权限。
13. Given 用户在工作群输入多行文本，When 输入并发送，Then 输入区可正常输入、占满宽度、自动增高，消息带发送者身份出现在时间线。
14. Given 群内有真人消息与 Bot 消息，When 浏览会话，Then 两者使用同一套消息呈现，顺序与 Hub 群内顺序一致。

## 管理员与主持

15. Given 群内存在主持管理员，When 用户发送未点名的普通消息，Then 由群主的主持管理员先应答。
16. Given 用户发送 `@名字`，When 消息发出，Then 被点名者应答，点名不被主持规则覆盖。
17. Given 普通成员与管理员，When 分别使用 `@all`，Then 只有管理员能召集全体。
18. Given 管理员 Bot，When 它改名、改公告、改应答模式、增删成员、移交主持权，Then 操作生效且用户可见。
19. Given 主持管理员，When 尝试未移交即离群，Then 被拒绝并提示需先移交主持权。
20. Given 主持管理员因所有者退群而离群，When 用户发送普通消息，Then 进入无主持状态，普通消息按「每人轮流」应答，点名仍精确生效。
21. Given 管理员 Bot，When 尝试批准任何人的**跨用户任务**，Then 被拒绝（跨用户任务的审批只能是任务所有者本人）。
21a. Given 群主的主持管理员，When 群内出现一条未点名的普通消息，Then 该消息直接进入主持管理员的群内会话并由它作答，**不产生待审批任务**；它是否征询用户、是否自主行动由其自身记忆与提示词决定；其工具调用仍受权限预约束缚。

## 解散权限

22. Given 群主，When 尝试解散，Then 可解散，需二次确认。
23. Given 群主的主持管理员 Bot，When 它发起解散，Then 可解散，结果与群主解散一致。
24. Given 其他成员的管家 Bot、真人管理员或普通成员，When 尝试解散，Then 被拒绝且不提供该操作。
25. Given 群内解散与 Hub 管理端解散同一群，When 分别执行，Then 结果一致：邀请撤销、未完成任务取消、历史只读保留。
26. Given 无主持管理员状态，When 查看解散入口，Then 仅有群主可发起，无 Bot 可解散。

## 工作目录与群级权限

27. Given 群主或管家 Bot 设置了群工作目录，When 任一成员在该群的 Bot 开始工作，Then 其 Session 建在该群目录下（覆盖 Bot 自有目录）。
28. Given 群主设置了群级权限，When 任一成员在该群的 Bot 工作，Then 以该群级权限运行。
29. Given 非群主（含真人管理员、Bot），When 尝试设置群级权限，Then 被拒绝。
30. Given 设置群工作目录时本机无法征求同意，When 提交，Then 提示无法完成且目录保持不变。

## 侧栏菜单与未读

31. Given 工作群会话行，When 右键，Then 菜单项与原群聊房间菜单对齐：置顶/取消置顶、标为未读、群设置、重命名群聊、复制对话 ID、从侧栏隐藏、解散。
32. Given 侧栏「群设置」，When 点击，Then 打开与原群聊一致的入口并定位到该群。
33. Given 侧栏「重命名群聊」，When 点击，Then 按原群聊方式进入改名态。
34. Given 一条会话，When 「标为未读」后打开它，Then 本地标记清除；同期 Hub 新消息计数仍独立显示与消减。

## 核心状态变化

35. Given A @ 了 B 的 Bot，When 任务待审批/进行中，Then 群内只显示脱敏进度，不显示成果内容。
36. Given B 批准执行完成并分享，When 分享成功，Then 群内出现一条以该 Bot 身份呈现的发言，**所有群成员都能看到正文**，且**附件对全群可下载**，可被回复与引用，不重复。
37. Given B 拒绝或取消任务，When 任务进入终态，Then 群内不产生任何 Bot 发言，附件仍不可被他人下载。
38. Given 新建群时管理员 Bot 无法开场，When 群打开，Then 显示可解释的降级状态而非空白，群仍可发消息。

## 原群聊能力对齐

39. Given 一条消息，When 用户添加表情反应，Then 气泡下方出现该反应；**其他成员重新打开群也能看到**；点击自己加的反应可撤销，**他人的反应不提供撤销操作**。
40. Given 输入区，When 使用听写，Then 语音转文字填入输入框；群内不出现语音聊天入口。
41. Given 群内消息超过一页，When 持续向上滚动，Then 能加载更早消息，不重复、不丢失已加载内容。

## 重要边界

42. Given 群内尚无任何消息，When 打开群，Then 呈现明确初始状态而非空白。
43. Given 发送失败或发送中 Hub 断线，When 查看，Then 显示「未送达」并保留草稿；恢复后按序补拉且不重复。
44. Given 目标 Bot 已被移除，When @ 它，Then 明确提示不可用，不生成任务。
45. Given 某成员被移出群，When 查看成员列表，Then 其名下所有 Bot 一并消失，其管家 Bot 不再显示 `Admin`。
46. Given 历史工作群，When 升级后打开，Then 不出现补写的开场、不追溯管理员标识，原有内容不变。

## 保持不变

47. Given 原群聊，When 完成建群、聊天、改设置、右键菜单、删除/归档，Then 行为与数据与改造前完全一致。
48. Given Hub 离线，When 使用私聊、普通群聊与本地 Bot，Then 一切照常，仅工作群受限。

## 视觉一致性（Web 端验收）

49. Given 固定窗口尺寸、主题与缩放，When 在 Web 端逐屏对照原群聊与工作群的主聊天区、输入区、侧栏会话行与右键菜单、群设置页、群详情页，Then 结构、间距、字号、配色、控件与交互状态一致（工作群专属元素除外，其只要求沿用同一设计语言）。
50. Given 切换主题与缩放比例，When 重复上述对照，Then 一致性结论不变。

# 需求摘要

```text
本次要解决：
- 工作群功能未完整对照原群聊，用户感知为「另一个产品」。
- 新建工作群没有原群聊式初始化，打开即空白会话。
- 工作群侧栏缺少原群聊的右键菜单（如删除）。

核心变化：
- 工作群以原群聊的界面、消息呈现、输入区、成员区、设置、详情与侧栏菜单为基准逐项对齐。
- 新群由主持管理员 Bot 发开场；创建者至多带 1 个自己的管家 Bot，该 Bot 自动入群并主持。
- 建群下限 2 个 Bot（与原群聊一致）；单 Bot 不能建群；邀请同事可选、可后补。
- 其他 Bot 不限数量，但每位成员名下合计 ≤12（含其管家 Bot），各自独立计数。
- 已入群的管家 Bot 都具 Admin 身份；只有群主的管理员主持默认应答；主持权移交与离群按原群聊规则，无主持时按每人轮流应答。
- 解散按原群聊口径：群主、群主的主持管理员 Bot、Hub 管理端可解散。
- 工作目录与群级权限按原群聊口径：群目录覆盖成员自有目录、群权限下发全群，权限仅群主可设。
- 补齐表情反应（全群可见、只能撤销自己的）、听写、向上加载更早消息。
- 侧栏右键菜单对齐原群聊（7 项含解散）；群设置打开全局设置页定位该群；未读采用 Hub 计数 + 本地标记双机制。
- Bot 成果被分享后，以 Bot 身份广播正文，且附件同步对全群开放下载。

关键规则：
- 一致性针对界面与交互，不改变执行授权：**他人委托的跨用户任务**只产生待审批任务，只有所有者本人可批准，管家 Bot 不代批。
- **主持管理员应答群内普通消息不走逐条审批**：消息直接进入它的群内会话，是否询问/自主决策由其记忆与提示词决定，工具调用受其权限预约束缚（D2、R14a）。
- 归属原则：每位成员只管理自己名下的 Bot；管家 Bot ≤1、本人 Bot ≤12。
- 群内解散与 Hub 管理端解散结果必须完全一致。
- 历史工作群不做任何处理。
- 原群聊代码、行为与数据完全不改。

必须关联检查：
- 原群聊全部能力逐项对照结果（复刻 / 适配 / 已裁决替换）。
- 侧栏：7 项菜单、置顶/隐藏、未读双机制、审批提示。
- 群设置入口（全局设置页）与既有详情抽屉的关系。
- 管家 Bot 的身份来源与发布路径、主持权转移与空缺、解散权、设目录权。
- 归属与配额校验：管家 ≤1、本人 Bot ≤12，需在本人加入、他人邀请、建群自动加入三条路径同时拦截。
- 工作目录与群级权限按原群聊放开后对既有禁止条款的取代，以及执行侧仍需所有者审批的底线。
- 向上翻页、表情反应跨用户存储与撤销鉴权、听写在群内的可用性。
- 分享时正文与附件同时扩为全群可见。
- 桌面端与 Web 端在固定尺寸/主题/缩放下的视觉一致性（Web 端承担验收）。

明确不做：
- 第二套群聊 UI 或导航；修改原群聊代码。
- 用户账号/头像体系。
- 群聊语音聊天（原群聊群内本身不提供）。
- 历史工作群的迁移与回填。
- 绕过审批的自动轮次与 Bot 自动接力。

尚未确认：
- 无关键待确认问题。
- 实现阶段需落地：群目录在其他成员 Host 上的本机确认方式（D1 残留风险）。
```
