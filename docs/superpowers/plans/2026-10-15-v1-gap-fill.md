**当前行为:** `WorkgroupView` 从未被 import；`isWorkgroupSession` 零调用点；`wg:` 会话渲染为空会话。
**修改内容（落点已变更，理由为实测结论）:**
原文写的「在 `conversation.content` 的 `session-maybe` 层分流」**不可行**：`ui-slots` 的 `registerFactory`（`packages/client/ui-slots/src/index.ts:1021-1034`）对二次定义直接抛 `already has a definition`，`conversation.content` 无法再影射；且 `useFactorySlotRuntime` 的局部槽由出现点选定。`layout.selectPanel` 对未注册 panel 抛错，故也不能注册 `main`。因此改为：
1. **overlay 落点**：`shadow('shell.overlay', { id: 'bot-workgroup', order: 45, inject: overlayFace }, WorkgroupPane)`。`.bt-pane` 的 `z-index: 45` 高于 `.bt-panel` 的 `40`，面板覆盖对话区，无需额外门控。
2. **身份分流**：按 `isWorkgroupSession(sessionId)`（`wg:<roomId>`）判定，不是按面板或群聊 id。
3. **进入顺序（本次发现的真实缺陷）**：`sessions.retain` 经 `manager.resolveTarget` 对未知 id 抛 `sessions.retain: unknown session`，而工作群由 Hub 拥有、本机从不创建该 Session，故「先导航再渲染」必然抛错。新增 `enterWorkgroup`：先 `sessions.create({ sessionId: 'wg:<roomId>' })`（Host 对磁盘无记录的 id 沿用原 id）再 `openSession`；`create` 失败则上报且**不导航**。
4. **两处 bounce 例外**：`index.js` 的 `home()` 与 `sidebar.js` 的 `useLandOnMainBot` 原本会把非 Bot 会话弹回主 Bot，工作群会话需让位，否则进入后被弹走。
**对应需求:** Requirement WP-A0；Design「方案 A」（**Design 结论须同步回写，见下**）。
**依赖:** A1。
**验证方式:** `npx vitest run integrations/workgroup/tests/`；真实浏览器下打开工作群看到群界面，且普通会话/普通群聊不受影响。

     - **(a) 扩 Hub 契约**：新增提及列/表 + 新迁移（`0008_message_replies.sql` 是先例）+ 更新 `server/contracts/` 权威规范 + 再生成 `application/integrations/workgroup/protocol/` 客户端类型。代价：跨边界契约变更，须同步两端与文档。
     - **(b) 在 `body` 内编码**：不改契约，提及以约定文本表达。代价：「稳定 ID」只能靠解析约定维持，引用/搜索/导出都要跟随该约定，且改名后的历史消息处理需另行定义。
   - 另外，「远程 @ 只生成**待审批任务候选**」还缺一条通道：Hub 有 `POST /api/v1/rooms/:roomId/tasks`（`server/src/api/tasks.js:73-88`，入参 `ownerUserId`/`targetBotId`/`description`），但 `hub-*` 端点列表（`host/channel.js:278-304`）**没有**创建任务这一项，`integrations/workgroup/client/index.mjs` 也未暴露该方法。需新增 `hub-create-task` 通道，并明确"目标 Bot 如何从目录选定（`GET /bots/directory`）"与"任务所有人是谁"。

4. **A5-3「附件」在 Hub 语义里不是"发一条带附件的消息"（M2 执行期间查明，需你裁决）。**
   - 事实：附件 API 完备且受 ACL 保护（`server/src/api/artifacts.js` 上传/列表/读取/内容/分享；`modules/artifacts/store.js:147` 表含 `task_id`、`room_id`、`acl_json`），但表结构**没有 `message_id` 外键** ⇒ 附件只能挂在**任务**下，不能挂在消息下。
   - 因此「用户选择文件 → 上传到 Hub 附件库」在当前契约下只能表达为"给某任务上传附件"，而"在聊天里发附件"需要契约变更（新增消息-附件关联）或改用"发消息 + 附任务"的组合语义。
   - 传输面另有约束：浏览器不能直连 Hub（`credentials: 'same-origin'`），须新增宿主上传端点并处理 `maxUploadBytes` 与二进制体。
   - 验收标准 4 的「非接收人无法下载」由 `acl_json` 保证，但**必须有 L 级实测**才算证据（当前未做）。

5. **工作群「重入入口」缺失（A2 执行期间发现，需求 WP-A0 隐含）。** `TeamSidebar` 的 `order` 只遍历 `roster.bots`/`roster.rooms`/`roster.agents`，`wg:` 会话不在其中，所以创建后离开该视图就**无法再次进入**。Hub 客户端已有 `GET /rooms` 与 `hub-directory` 可用但客户端未消费。新增入口属于 M3+ 的新 Plan（用户要求 M2 之后先立 Plan 再执行），本轮只记录不实现。
