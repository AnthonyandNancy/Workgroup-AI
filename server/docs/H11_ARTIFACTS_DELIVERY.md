## 开发中被暴露并修复的四个真实缺陷

### 缺陷 1（安全相关）：`storage_key UNIQUE` 让"上传同一文件"变成 500

内容寻址存储意味着相同内容产生**相同** `storage_key`，而原始 schema 对该列设了 `UNIQUE`。第二个上传者插入时撞约束，路由返回 500。

**这不是"边界情况"**：在协作工具里"别人已经上传过这个文件"是最常见的情形之一。修正是把唯一性从"对对象的引用"移到"对象本身"——多行可以指向同一对象，读取时重算哈希才是真正的保证。

### 缺陷 2（可用性，最严重）：非 ASCII 文件名让下载**完全失败**

真实运行时 B 下载返回 **500**：

```
ERR_INVALID_CHAR: Invalid character in header content
```

根因：`content-disposition` 头里直接写了原始文件名，而 **HTTP 头只允许 ASCII**。中文项目里"报表.csv"是常态，所以这不是边缘情况——**任何中文名文件都无法被接收人下载**。

**为什么单元测试没抓到：** 测试用 `server.inject`，它不经过 Node 的 HTTP 头序列化。**只有真实 HTTP 才暴露这个缺陷。** 这是本轮最有价值的一条经验：`inject` 覆盖不了协议层的约束。

修复：按 RFC 6266 同时给出 `filename="Q4__.csv"`（ASCII 回退）与 `filename*=UTF-8''Q4%E6%8A%A5%E8%A1%A8.csv`（精确名）。真实验证：

```
disposition: attachment; filename="Q4__.csv"; filename*=UTF-8''Q4%E6%8A%A5%E8%A1%A8.csv
```

并补了两个测试（非 ASCII 名、ASCII 名同时提供两种形式）。

### 缺陷 3：`contentType` 返回了但从未存储

创建时返回 `contentType`，但没写进 ACL，读回永远是 `octet-stream`。修复：存入 ACL，`shareArtifact` 与损坏兜底路径都保留它。

### 缺陷 4：Fastify 5 的 `addContentTypeParser` 没有"按名注册"的替代方案

我先后尝试了三种写法，全部失败：
- 逐个注册具体类型 → 未列出的类型 415
- `application/*` → 不是通配符，同样 415
- 最终用 `'*'`（Fastify 自己的 catch-all）+ 显式覆盖 `text/plain`（它内置 string parser，会返回字符串而非字节）

**这个过程揭示了一个我最初写对的答案被自己改错了**：第一版就是 `'*'`，我误以为它不工作而改成枚举，反而制造了缺陷。教训是：改对了的代码要保留证据，而不是凭印象重构。

## 关键设计决定

### 1. 对象名由内容决定，用户文件名永不成为路径
存储路径 = `artifactsDir/<hash前2>/<hash次2>/<hash>`。哈希即对象名，因此相同内容只存一份，且客户端提供的文件名不可能构成路径穿越——它只作为元数据列。

### 2. 成员资格与 ACL 是两次独立检查
`mayReadArtifact` 先查 `room_members`（`removed_at IS NULL`），再查 ACL。**被移除的接收人失去访问**，即使 ACL 里仍列着他（真实验证确认）。

### 3. 拒绝不确认存在
非成员读真实 id 与伪造 id 的响应**逐字节相同**（真实验证 `一致: true`）。删除路径同样先查成员资格，避免"你无权删"泄漏存在性。

### 4. 每次下载重算哈希
`readArtifact` 从磁盘读回后重算 SHA-256 与记录比对，不一致返回 **500 `ARTIFACT_BYTES_CHANGED`** 而不是把被篡改的内容发给接收人。测试直接改写磁盘文件验证这条。

### 5. 删除时才清理字节，且仅在无人引用时
`deleteArtifact` 删行后检查同 `sha256` 是否还有其他行；只有最后一个引用被删才 `rmSync`。测试用"两份相同内容删一份"验证——过早清理会破坏另一份。

### 6. 上传先写文件、后写行
崩溃时留下的是**无引用的对象**（无害、可回收），而不是**指向不存在字节的行**。

### 7. 推送不带文件名
`publishArtifactChange` 只发 `artifactId` + `kind`。文件名是群成员**未必有权知道**的元数据；有了 id，有权的人可以自己去取。

### 8. 审计只记哈希与大小
`artifact.uploaded` 的 `safe_details_json` 含 `sha256`、`sizeBytes`、`recipients` 数量，**不含文件名也不含内容**。
